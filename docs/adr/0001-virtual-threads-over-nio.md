# 并发模型：虚拟线程 + 阻塞式 Socket（不用 NIO Selector / Netty）

编译目标 JDK 21，每条 Peer 连接由一个虚拟线程以阻塞式 Socket 驱动；不引入 Netty，也不手写 NIO Selector 事件循环。理由：目标量级是数百条并发长连接，虚拟线程让代码保持朴素的阻塞模型，维护成本最低，且不为库的使用者转嫁框架依赖。ttorrent（无人维护、平台线程模型）与 Netty（框架概念负担大于协议学习收益）均不采用。

## Consequences

- JDK 21/22/23 运行时下，`synchronized` 内长时间阻塞会 pin 载体线程（JDK 24 的 JEP 491 才修复）；锁内长等待一律用 `ReentrantLock`。
- 运行环境面向 21/25/26，CI 测试矩阵覆盖三者。
- 后续若出现单机万级连接需求，本决策需重估（重写为事件驱动模型的成本约等于一次季度级重构）。
